    What needs your attention?

    Each PR gets one queue, using the first matching rule below. “My PRs” is a separate view across all queues.

    What counts as a response?

    A later conversation comment, inline comment, or submitted review from you anywhere on the PR clears an earlier direct mention. A push alone does not. Description mentions put a PR in the pool, but do not create a high-priority request.

    Human activity only

    Bot comments, reviews, thread replies, bot-authored commits, and comments starting with /ci do not drive priorities or activity sorting. CI trigger comments also do not count as a response to a mention. GitHub bot accounts and known review/CI service accounts are excluded. Reviewer and assignee fields still describe your current responsibilities.

    Signals, not certainty

    Follow-ups and responsibility are heuristics, with evidence shown per PR. Commit timestamps can be affected by rebases. A resolved thread does not erase an unanswered direct mention. Edited comments use their creation time; we cannot reconstruct when a mention was added. Team mentions are not individual mentions.

    Snapshot scope

    The local server refreshes PRs when requested or when you open a preview. Refresh-on-return requires clicking Open pull request or a row’s GitHub shortcut; switching tabs alone does not trigger it. Use the API indicator to freeze refreshes across all sessions. Authentication stays on the server; this page uses no credentials or third-party scripts. The Ready view checks current maintainer approvals, CI results, and GitHub mergeability on refresh. Merging takes place on GitHub.
